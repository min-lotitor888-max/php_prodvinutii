# Домашнее задание: база данных (SQL + PHP-обёртка)

## Описание проекта

Решение состоит из двух частей:

1. **task-02 — SQL** — схема из пяти связанных таблиц, наполнение данными и агрегатные запросы (задание со звёздочкой).
2. **task-03 — PHP-обёртка** — CRUD-обёртка над таблицами на PDO: интерфейс `DatabaseWrapper`, абстрактный класс `BaseTable` и классы-обёртки `Shop`, `Order`, `Client`.

## Структура проекта

```
task-02/
    setup.sql          -- создание таблиц и наполнение данными
    queries.sql        -- агрегатные запросы (задание со звёздочкой)
task-03/
    database.php       -- подключение к SQLite, автосоздание БД
    DatabaseWrapper.php-- интерфейс CRUD
    BaseTable.php      -- абстрактный класс с общей реализацией CRUD
    Shop.php           -- обёртка таблицы shop
    Order.php          -- обёртка таблицы order
    Client.php         -- обёртка таблицы client
    index.php          -- демонстрация работы всех методов
```

## Схема данных

| Таблица | Что хранит | Связи |
|---|---|---|
| `shop` | название, адрес | — |
| `client` | телефон, имя | — |
| `product` | название, цена, количество, магазин | `shop_id` → `shop` |
| `order` | дата и время создания, клиент, магазин | `client_id` → `client`, `shop_id` → `shop` |
| `order_product` | какой продукт вошёл в заказ и по какой цене | `order_id` → `order`, `product_id` → `product` |

Пара «кто кому продал» в заказе — это `shop_id` (кто продал) и `client_id` (кому продал). Таблица `order_product` реализует связь «многие ко многим» между заказами и продуктами и хранит цену на момент покупки.

## SQL-часть (task-02)

**setup.sql**

- `PRAGMA foreign_keys = ON` — включает проверку внешних ключей;
- `DROP TABLE IF EXISTS` — схему можно запускать повторно;
- имя `"order"` всегда в двойных кавычках — это зарезервированное слово SQL;
- в каждой таблице не менее пяти строк: 5 магазинов, 5 клиентов, 5 продуктов, 5 заказов и 6 позиций в `order_product`.

По условию «не для каждого магазина могут существовать продукты и заказы»: у магазина «Центральный» (id 5) нет ни продуктов, ни заказов — FOREIGN KEY это не запрещает.

**queries.sql (задание со звёздочкой)**

1. Сумма покупок клиента в период ±3 дня от дня рождения — окно считается через `julianday`, поэтому корректно обрабатывается и стык годов, и границы включительно.
2. Заказы, в которых цена продукта отличается от текущей в таблице `product`, и разница: в данных расхождение одно — заказ 5, «Смартфон» куплен за 29 000 при текущей цене 30 000 (разница 1 000).
3. Самый прибыльный магазин и магазин с наибольшим числом покупок: «Магазин на Ленина» — 109 000 суммой и 2 заказа.

## PHP-обёртка (task-03)

**Интерфейс `DatabaseWrapper`** — контракт из четырёх методов:

| Метод | Что делает | Возвращает |
|---|---|---|
| `insert(array $tableColumns, array $values)` | вставляет строку и возвращает её целиком | `array` |
| `update(int $id, array $values)` | обновляет поля записи по id | `array` |
| `find(int $id)` | находит запись по id | `array` (пустой, если нет) |
| `delete(int $id)` | удаляет запись по id | `bool` |

**`BaseTable`** — абстрактный класс с общей реализацией всех методов:

- имя таблицы хранится в свойстве `$table` и подставляется в кавычках — обёртка работает и с таблицей `"order"`;
- значения всегда подставляются через подготовленные запросы (placeholders `?`) — защита от SQL-инъекций;
- `insert()` после вставки возвращает полную запись через `find((int) $pdo->lastInsertId())`.

**Классы-обёртки** — по три строки каждый, вся магия в наследовании:

```php
class Shop extends BaseTable
{
    protected $table = 'shop';
}
```

**`database.php`** — при первом запуске сам создаёт файл `database.sqlite` и накатывает `setup.sql` из task-02, затем возвращает готовый PDO с включёнными внешними ключами и режимом выборки `FETCH_ASSOC`.

## Что демонстрирует

- интерфейсы как контракт: `BaseTable` обязан реализовать все четыре метода `DatabaseWrapper`;
- наследование и повторное использование кода: три класса-обёртки написаны без единого дублированного запроса;
- работу с PDO: подготовленные выражения, `lastInsertId`, `rowCount`, режим исключений;
- работу с SQLite: файловая БД, `AUTOINCREMENT`, `PRAGMA foreign_keys`;
- FOREIGN KEY: при попытке вставить заказ с несуществующим `client_id` или `shop_id` SQLite выбросит ошибку.
