## Задание 2. Трейты

Созданы два трейта с разным смыслом, но одинаковым методом `authenticate()`:

| Трейт | Приватные свойства | Что проверяет |
|---|---|---|
| `AppUserAuthentication` | `$appLogin`, `$appPassword` | вход в приложение |
| `MobileUserAuthentication` | `$mobileLogin`, `$mobilePassword` | вход в мобильное приложение |

Логины и пароли заданы прямо в трейтах:

```php
private $appLogin = 'app_user';
private $appPassword = 'app_pass';
```

```php
private $mobileLogin = 'mobile_user';
private $mobilePassword = 'mobile_pass';
```

Класс `User` подключает оба трейта. Так как метод называется одинаково, конфликт решается через `insteadof` и `as`:

```php
use AppUserAuthentication, MobileUserAuthentication {
    AppUserAuthentication::authenticate insteadof MobileUserAuthentication;
    MobileUserAuthentication::authenticate as authenticateMobile;
}
```

Метод `login()` сначала проверяет данные для обычного приложения, затем — для мобильного. Если не подошло ни то, ни другое, выводится сообщение об ошибке.

### Результат

```text
Пользователь авторизован как пользователь приложения.
Пользователь авторизован как пользователь мобильного приложения.
Неверный логин или пароль.
```

### Запуск

```bash
php task-02/index.php
```

## Задание 3. Итераторы и магия

### Класс Person

У класса `Person` есть приватные свойства `login`, `name`, `age` и магические методы:

| Метод | Что делает |
|---|---|
| `__get()` | возвращает значение свойства |
| `__set()` | изменяет значение свойства |
| `__sleep()` | указывает, какие свойства сериализовать |
| `__wakeup()` | вызывается при десериализации, приводит возраст к числу |
| `__toString()` | возвращает строковое представление объекта |

В `index.php` объект создаётся, сериализуется, логин меняется через `str_replace`, затем объект десериализуется и выводятся его свойства.

Проверяются два случая замены:

- **строка такой же длины** (`ivanov` → `petrov`) — десериализация проходит успешно;
- **строка другой длины** (`ivanov` → `sidorov`) — десериализация не удаётся.

Это происходит потому, что в сериализованной строке хранится длина: `s:6:"ivanov"`. Если вставить строку из 7 символов, а длина останется 6, данные станут некорректными. В выводе нулевые байты обозначены как `\0` для читаемости.

### Результат

```text
Объект: ivanov: Иван, возраст 20
Логин через __get: ivanov
После __set: ivanov: Иван, возраст 21
Сериализованная строка: O:6:"Person":3:{s:13:"\0Person\0login";s:6:"ivanov";s:12:"\0Person\0name";s:8:"Иван";s:11:"\0Person\0age";i:21;}
Замена на строку такой же длины: O:6:"Person":3:{s:13:"\0Person\0login";s:6:"petrov";s:12:"\0Person\0name";s:8:"Иван";s:11:"\0Person\0age";i:21;}
После десериализации: petrov: Иван, возраст 21
Свойства: логин = petrov, имя = Иван, возраст = 21
Замена на строку другой длины: O:6:"Person":3:{s:13:"\0Person\0login";s:6:"sidorov";s:12:"\0Person\0name";s:8:"Иван";s:11:"\0Person\0age";i:21;}
Десериализация не удалась: длина строки в данных не совпала.

Список людей:
0: ivanov: Иван, возраст 20
1: petrov: Пётр, возраст 25
2: sidorova: Анна, возраст 22
```

### Класс PeopleList

`PeopleList` реализует интерфейс `Iterator` и хранит массив объектов `Person`. Благодаря этому список можно перебирать через `foreach`, а не обращаться к элементам напрямую.

Методы итератора:

- `rewind()` — начинает с первого элемента;
- `current()` — возвращает текущий объект `Person`;
- `key()` — возвращает индекс;
- `next()` — переходит к следующему элементу;
- `valid()` — проверяет, есть ли ещё элементы.

Для вывода объекта используется `__toString()`.

```bash
php task-03/index.php
```
